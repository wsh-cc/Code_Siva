# OCHAT 升级记录

这份记录用来说明项目从基础聊天演示版到当前版本主要改了哪些地方。重点不是罗列所有代码细节，而是把功能变化、数据变化和运行方式记录清楚，方便后面写报告或答辩时回看。

## 主要变化

这次升级后，客户端不再只是简单的登录窗口加聊天窗口，而是按常见聊天软件的使用方式重新组织了界面。桌面端使用左侧导航、中间列表、右侧聊天区的结构；Web 端则改成以聊天内容为中心的浏览器界面，历史会话、好友、群聊和申请放到侧栏里处理。

服务端也补上了更多业务接口，包括会话列表、好友申请、群聊邀请、未读消息、消息已读、群成员角色、群备注和消息撤回等。这样客户端界面上的操作基本都能落到真实后端逻辑，不只是前端展示。

## 客户端调整

- 桌面端增加了消息、好友、群聊、申请等视图。
- 聊天区拆成会话标题、消息区域、工具栏和输入区。
- 好友和群聊列表显示最近消息、未读数量和在线状态。
- 个人资料窗口补充了生日、性别、年龄、地址、联系方式、头像和签名。
- 表情、文件、图片、搜索、撤回等操作集中放在聊天相关区域。
- Web 端增加登录、注册、聊天、文件、群聊、资料编辑和连接设置等页面交互。
- Web 聊天界面调整为更轻的玻璃风格，减少传统气泡的厚重感。

## 服务端调整

- 新增 `conversations.list`，统一返回私聊和群聊会话。
- 新增 `friends.request`、`friends.requests.list`、`friends.requests.respond`，用于好友申请流程。
- 新增 `groups.invite.request`、`groups.invitations.list`、`groups.invitations.respond`，用于群邀请流程。
- 新增 `messages.read` 和 `unread.updated`，用于未读消息同步。
- 增加群角色、群昵称、群备注、群重命名、退群和解散群聊相关处理。
- 文件上传和下载继续由服务端做权限检查，避免客户端绕过限制。

## 数据库变化

数据库在原有用户、好友、群聊、消息和文件表的基础上，补充了申请和已读相关数据。

- `friend_requests` 记录好友申请。
- `group_invitations` 记录群聊邀请。
- `message_reads` 记录每个用户读过的消息。
- `users` 增加生日、性别、地址和年龄等资料字段。
- `group_members` 增加角色排序、群内昵称和个人群备注。

老数据库启动时会自动补充缺失字段，方便从旧版本继续演示。

## Web 化补充

Web 端没有重新写一套后端业务。浏览器访问 `web_client.server` 提供的 HTTP 服务，HTTP 服务内部复用 `client.api.OchatClient` 连接原来的 TCP 聊天服务端。

这样做的好处是桌面端和 Web 端使用同一套后端能力，业务规则不会分裂。比如好友权限、群成员权限、文件访问权限、消息历史和未读数量，都仍然由原来的服务端统一处理。

## 运行方式

SQLite 演示模式：

```powershell
python start_server.py
python start_client.py
python start_web_client.py
```

Web 端访问：

```text
http://127.0.0.1:8080
```

MySQL 模式：

```powershell
python start_server.py --db-backend mysql --mysql-user root --mysql-password 你的密码 --mysql-database ochat
```

运行测试：

```powershell
python -m pytest -q
```

## 检查重点

升级后重点验证这些流程：

1. 注册、登录、退出和重新登录。
2. 好友申请、同意、拒绝、备注、分组和删除。
3. 私聊消息发送、历史记录、未读数量和撤回。
4. 群聊创建、邀请、同意入群、成员管理、群备注和退群。
5. 图片预览、文件上传、文件下载和权限校验。
6. Web 端与桌面端同时在线时的消息同步。

这些流程跑通后，基本可以说明当前版本已经不只是界面升级，而是把聊天系统的主要业务链路补完整了。
