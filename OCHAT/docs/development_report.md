# OCHAT 在线互动聊天系统实践报告草稿

## 1. 项目概述

OCHAT 是面向《信息系统设计与开发实践》课程的在线互动聊天系统。项目采用客户端、服务端、数据库分离的三层结构，使用 Python 实现图形界面、Socket 网络通信、多线程并发处理和 MySQL 数据持久化。

系统主要目标是完成用户注册登录、个人资料管理、好友管理、在线状态显示、一对一聊天、群聊、文件/图片发送、消息历史记录、消息搜索和基础安全防护。

## 2. 需求分析

### 2.1 用户模块

- 用户注册：校验用户名、密码格式，防止重复注册。
- 用户登录：用户名和密码不能为空；验证用户名和密码，维护在线状态。
- 用户退出：关闭会话并更新在线状态。
- 个人资料管理：支持昵称、签名、联系方式、头像地址修改。

### 2.2 好友模块

- 添加好友：根据用户名添加好友关系。
- 删除好友：删除当前用户侧好友关系。
- 修改备注：支持好友备注和好友分组。
- 在线状态：好友列表展示在线或离线状态。

### 2.3 通信模块

- 私聊：好友之间实时发送文本消息。
- 群聊：创建群聊、邀请成员、查看群成员并发送群消息。
- 历史记录：重新打开聊天窗口后加载历史消息。
- 消息搜索：按关键词搜索当前用户可见的消息。
- 消息撤回：客户端提供撤回按钮，服务端进行发送者权限检查。

### 2.4 文件与图片模块

- 文件上传：支持常见文档、图片和压缩包类型。
- 文件保存：接收方可保存当前聊天中有权限访问的文件。
- 图片发送：图片作为特殊消息类型保存并展示。
- 上传限制：限制文件后缀和 10 MB 大小，避免危险文件直接上传。

## 3. 系统设计

### 3.1 总体架构

系统分为三层：

- 客户端：使用 Tkinter 实现登录、注册、好友列表、群聊列表、聊天窗口和文件选择。
- 服务端：使用 TCP Socket 与 JSON Lines 协议通信，使用多线程处理多个客户端连接。
- 数据库：使用 MySQL 保存用户、好友、群聊、消息和文件元数据。

### 3.2 通信协议

客户端和服务端之间使用一行一个 JSON 对象的协议。每个请求包含 `action` 和 `request_id`，服务端响应时返回同一个 `request_id`，避免多个请求并发时响应混淆。

示例：

```json
{"action":"messages.direct.send","request_id":"...","receiver_id":2,"content":"hello"}
```

### 3.3 并发设计

服务端主线程负责监听端口，每个客户端连接由一个独立线程处理。在线会话保存在内存字典中，并使用线程锁保护共享状态。发送消息时，服务端根据接收者或群成员列表推送实时事件。

## 4. 数据库设计

主要数据表如下：

- `users`：保存用户账号、密码哈希、昵称、头像、签名、联系方式。
- `friendships`：保存好友关系、备注、分组。
- `chat_groups`：保存群聊基本信息和创建者。
- `group_members`：保存群成员、角色、群内别名。
- `messages`：保存私聊和群聊消息、消息类型、状态和发送时间。
- `files`：保存上传文件原始文件名、存储名、大小和 MIME 类型。

MySQL 建表脚本位于 `database/schema_mysql.sql`。

## 5. 安全设计

- 密码不明文保存，使用 PBKDF2-SHA256、随机盐和多轮迭代生成密码摘要。
- 用户名限制为 3 到 20 位字母、数字或下划线。
- 服务端统一校验登录状态、好友关系、群成员身份和操作权限。
- 数据库访问使用参数化查询，降低 SQL 注入风险。
- 文件上传进行后缀、文件名和大小检查。
- 网络协议限制单包大小，同时与 10 MB 文件上传限制保持一致。



